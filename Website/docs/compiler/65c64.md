# 65C64 Code

The 65C64 back end (`CIR65Backend`) turns IR into 65C64 assembly.  The 65C64 was designed with C++
in mind: 32 bit registers that widen to 64 for a `long long`, 256 bytes of pseudo registers, and
multiply and divide instructions.  So its back end is simpler than the W65C816's: it allocates
registers and then tidies the text.

The calling convention, the registers and the pseudo registers are described with the processor,
in [Calling Convention](../65c64/calling-convention.md).  In short: arguments are pushed last first,
each at its own size, and removed by the caller; `this` is in X; the result is in A; V is the frame
pointer and W is always 0.

## Memory

| Address | Holds |
|---|---|
| `0000:0000` to `0000:00FF` | The pseudo registers |
| `0001:0000` | The program: code, then data |
| `001F:FFFF` | The top of the stack, which grows down |
| `00FF:0000` to `00FF:FFFF` | The emulator's devices |

Libc65's heap is below the stack, or above it when there is more than 2MB of memory.

## Register allocation

Each value's live ranges are worked out (with holes), weighted by how often it is used and 8 times
more for each loop it is in, and values are given homes heaviest first:

| Home | When |
|---|---|
| X or Y | Nothing that changes them (a call, the soft float routines, `mul` and `div`) happens while the value is live. |
| `[$00]` to `[$7F]` | No call is made while it is live. |
| `[$80]` to `[$FF]` | It is used in a loop: the function saves the pseudo registers it uses and restores them before it returns. |
| The frame | Everything else, `[1 + offset + V]`. |

A phi joins the values it takes when their ranges don't overlap, so most phis need no copies.
Instructions work wherever is shortest: in the result's home when the first operand is kept there
too (`add X, 1`, `shl [4], 2`), or through A.  A multiply by a constant of a few signed digits is
shifts and adds.  A function with nothing in its frame doesn't set V up.

## Passes over the code

After the code is written, three passes go over the text:

1. **Flags** (`CIR65Flags`).  The flags are followed through the code, and a `cmp` whose result the
   flags already hold is removed.
2. **Widths** (`CIR65Widths`).  The back end writes every instruction with A, B, X and Y 32 bits
   wide.  This pass works out which bits of each register are really read, then writes the code
   again with each register's width set only where it changes, a loop's widths set once before
   it.
3. **Last peephole** (`CIR65Peephole`).  What each register holds is followed through the code,
   and loads and copies of what a register already holds are removed.

## Start up

The start up, linked first so it is at `0001:0000`:

1. sets S to `$1FFFFF`, W to 0 and A, B, X and Y to 32 bits,
2. calls the init table (each global's constructor, in link order),
3. calls `main`,
4. calls Libc65's `atexit` functions, if `stdlib.cpp` is linked,
5. calls the fini table backwards (the global destructors), and stops with `main`'s result in A.

The reset vector is left to whatever loads the program.

## An example

The same `Sum` as on the [W65C816 page](w65c816.md#an-example):

```asm
		.section text._Sum__FPKst
		.global _Sum__FPKst
_Sum__FPKst:
		cpy A, [5 + S]				; piValues, into a pseudo register
		cpy [8 + W], A
		wth A, 16
		cpy A, [9 + S]				; uiCount, zero extended
		wthx A, 32
		cpy [4 + W], A
L1:
		; Sum.cpp(9): for (i = 0; i < uiCount; i++)
		cpy A, 0
		cmp A, [4]
		bras c, L5
		cpy Y, 0					; iTotal is kept in Y
		cpy X, 0					; i in X
		cpy [0 + W], 0
		bra L2
L5:
		cpy Y, 0
		bra L3
L2:
		; Sum.cpp(11): iTotal += piValues[i];
		cpy A, [0 + W]
		shl A, 1
		add A, [8]
		cpy B, A
		wth A, 16
		cpy A, [B]
		wthx A, 32:s				; sign extend the int16_t
		add Y, A
		; Sum.cpp(9): for (i = 0; i < uiCount; i++)
		add X, 1
		and X, 65535				; i is a uint16_t
		cpy A, X
		cpy [0 + W], A
		cmp X, [4]
		brac c, L2
L3:
		; Sum.cpp(13): return iTotal;
		cpy A, Y
L4:
		ret
```

The [65C64 instruction pages](../65c64/instructions/index.md) describe each instruction.
