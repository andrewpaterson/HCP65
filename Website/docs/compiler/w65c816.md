# W65C816 Code

The W65C816 back end (`CIR816Backend`) turns IR into W65C816 assembly.  The W65C816 is a hard
target for C++: one accumulator, 16 bits at most, no multiply or divide, mode bits that change
the size of an immediate, a 64KB bank that the program counter wraps in, and no call through a 24
bit pointer.  The compiler's job is to hide all of that.

## The model

The compiler uses one model, the equivalent of WDC's large model:

- **Far calls.**  Every function is called with `jsl` and returns with `rtl`, so code can be in
  any bank.
- **Far data.**  Globals are reached with long addresses (`lda [_gTable]:24`).  The data bank
  register isn't used, so it doesn't matter what an interrupt or `mvn` leaves in it.
- **Far pointers.**  A pointer is 4 bytes: a 24 bit address and a zero top byte.  It is loaded and
  stored as two 16 bit words, and followed through the direct page (`lda [[D + p]:24 + Y]`).  The
  top byte is always written as 0, so `==` and `!=` compare two words without masking.
- **16 bit registers.**  A, X and Y are 16 bits wide (`rep (m, x)`) at every function's entry and
  exit and at every label.  Code that wants 8 bits switches to them around the instruction.
- **`int` is 16 bits**, `long` 32 (see [Supported C++](language.md#a-16-bit-int)).

**Bank 0 holds no code.**  Only the stack, the direct page, the hardware vectors and a 4 byte `jml`
stub for each vector go there; the linker refuses any other section in bank 0.

## Calling convention

| | |
|---|---|
| Call | `jsl`, return with `rtl`.  m and x are 16 bit on entry and exit. |
| Arguments | In A, X and Y where they fit ([below](#register-arguments)); the rest pushed last first, each in 16 bit words (a `char` takes 2), and removed by the caller. |
| `this` | The first argument, so in A and X; pushed when the function returns 64 bits, as the hidden result pointer takes A and X. |
| Results | 8 and 16 bits in A; 32 bits and pointers in A (low word) and X (high word); 64 bit values and objects through a hidden pointer to where the result goes. |
| Kept by a call | D, the data bank, S and the mode. |
| Changed by a call | A, X, Y and the flags. |
| Variadic functions | Every argument pushed, after the default promotions (`float` is passed as `double`). |

### Register arguments

A function that isn't variadic takes its arguments in registers, whether it has C++ or C
linkage:

- Going through the arguments in order (a hidden result pointer first), each takes the next of
  A, X and Y if all its words fit.  A 32 bit value takes two registers, low word first.  An
  argument that doesn't fit is pushed, and a later, smaller one may still fit.
- The function's code is at its label plus a **suffix** naming where each argument word is: a
  dot, then `a`, `x` or `y` for a register or `s` for a pushed word, without the pushed words at
  the end.  `_Add__Fii.ax` takes two `int`s in A and X; `_Sum__FPKst.axy` takes a pointer in A
  and X and a `uint16_t` in Y.  A caller and a definition that disagree don't link.
- The plain label is an entry for callers that push everything (function pointers, vtables,
  thunks and assembly): it loads the registers from the stack and goes on to the body.

Every caller works out the same rule from the argument sizes alone.  Hand written assembly that
C++ calls defines the suffixed labels too.

## Frames

**The direct page is the frame.**  A function points D at its own stack frame, so its locals, its
temporaries and its arguments are all direct page operands, and every addressing mode works on
them: `inc [D + n]`, `pei [D + n]`, and following a far pointer straight from a local with
`lda [[D + n]:24 + Y]`.  Each function has its own D, so nothing needs saving across calls.

```asm
_Dot__FPC6SPointPC6SPoint.ax:
		phd						; the caller's D
		phx						; the register arguments, into the frame
		pha
		tsc
		sec
		sbc 30					; the frame
		tcs
		tcd						; D = S
		...
		tay						; keep the result's low word
		tdc
		clc
		adc 34					; S back above the frame and the register words
		tcs
		tya
		pld
		rtl
```

A frame of more than 256 bytes has its far part reached through X.  Frames over 48KB are an
error.

### Aligned frames

A direct page access costs a cycle more when D isn't on a page boundary.  For a function that
makes many direct page accesses, the prologue rounds D and S down to the page (`and 0xFF00`),
copies the arguments up to it, and keeps the old S in the frame for the epilogue.  It costs up to
255 bytes of stack a call, so it is only done where it pays and never for a function that may
recurse:

- **Estimated** (the default): a function with loops whose direct page accesses, weighted 8 for
  each loop they are in, are more than 3 times what aligning costs a call.
- **Measured** (profile guided): `CAsm65816Profile` runs the programs and counts each function's
  direct page accesses and calls, and whether it was ever entered again while running.
  `CCPP65Builder::SetFrameProfile` gives that to the back end, which aligns a function never seen
  recursing whose accesses are more than 3 times the cost and that saves at least a ten
  thousandth of the profiled cycles.

## Calls through pointers

The W65C816 has no `jsl` through a pointer, so a call through a function pointer or a vtable
pushes a return address and the target, then "returns" into it:

```asm
		phk						; return bank
		per L3 - 1				; return offset
		sep m
		lda [D + 29]			; target bank
		pha
		rep m
		lda [D + 27]			; target offset - 1
		dec A
		pha
		rtl
L3:
```

## Arithmetic

| Operation | How |
|---|---|
| 8 and 16 bit add, subtract, logic, compare | In line, through A. |
| 32 and 64 bit add, subtract, logic, compare | In line, 16 bits at a time with the carry between. |
| Shifts by a constant | In line, a byte at a time a word along where that's quicker. |
| Shifts by a variable | 16 bits in line; 32 and 64 bits call `R816_Shl32` ... |
| Multiply by a constant | Shifts and adds when they cost less than the call. |
| Multiply, divide, remainder | Runtime routines `R816_Mul16`, `R816_UDiv32` ...  `x / d` and `x % d` share one divide. |
| Signed comparisons | `sbc` and the n xor v test (`cmp` doesn't set v). |
| `__builtin_clz`, `__builtin_ctz` | `R816_Clz16` ... (a byte table). |
| `float` and `double` | Calls of `softfloatW65C816.asm`, with the operands left in the caller's frame. |

The multiply, divide and shift routines are in Libc65.  [W65C816 Runtime](../hcp65/runtime/w65c816.md)
describes them, their calling conventions and the choice between the table and table-free
multiplies.

## Assembly units

A unit `X.cpp` can have hand written assembly beside it, `XW65C816.asm`, which the W65C816 build
assembles instead of compiling the C++ (`CCPPCompileOptions::SetAssemblyUnits`).  Libc65's
`stringW65C816.asm` and `softfloatW65C816.asm`, and BaseLib's FAT file system, are written this way.  The
C++ stays as the reference and the version other processors build.

## Start up

`CCPPTargetW65C816::AppendStartUp` writes the start up a stand alone program links first.  It puts
the reset vector and a `jml` stub in bank 0, then:

1. switches to native mode with 16 bit registers, sets S to `$EFFF` and D to 0,
2. clears the bss (globals with no initialiser),
3. calls each entry of the init table (each global's constructor, in link order),
4. calls `main` with `jsl`,
5. calls Libc65's `atexit` functions if `stdlib.cpp` is linked,
6. calls the fini table's entries backwards (the global destructors),
7. stops with `stp`, `main`'s result in A.

A program the HCP65 kernal runs uses UserLib's `UserStart.asm` instead, which does the same and
then exits through the kernal.

## An example

```cpp
int32_t Sum(const int16_t* piValues, uint16_t uiCount)
{
	int32_t		iTotal;
	uint16_t	i;

	iTotal = 0;
	for (i = 0; i < uiCount; i++)
	{
		iTotal += piValues[i];
	}
	return iTotal;
}
```

compiles to this (some of it):

```asm
		.section text._Sum__FPKst
		.global _Sum__FPKst
_Sum__FPKst:						; the stack entry: the arguments into A, X and Y
		.width (A, X), 16
		.relax
		lda [S + 8]
		tay
		lda [S + 6]
		tax
		lda [S + 4]
		.global _Sum__FPKst.axy
_Sum__FPKst.axy:					; the register entry
		phd
		phy
		phx
		pha
		tsc
		tax
		sec
		sbc 47
		and 0xFF00					; an aligned frame: the loop pays for it
		tcs
		tcd
		...
L2:
		; Sum.cpp(11): iTotal += piValues[i];
		lda [[D + 23]:24]			; *piValues, through the far pointer in the frame
		sta [D + 31]
		asl A						; sign extend to 32 bits
		lda 0
		adc 0xFFFF
		eor 0xFFFF
		sta [D + 33]
		clc							; iTotal += it, a word at a time
		lda [D + 27]
		adc [D + 31]
		sta [D + 27]
		lda [D + 29]
		adc [D + 33]
		sta [D + 29]
		; Sum.cpp(9): for (i = 0; i < uiCount; i++)
		inx							; i is kept in X
		clc
		lda [D + 23]				; the pointer stepped, not i scaled
		adc 2
		sta [D + 23]
		lda [D + 25]
		adc 0
		sta [D + 25]
		cpx [D + 41]
		bcc L2
		...
		; Sum.cpp(13): return iTotal;
		ldx [D + 33]				; the result in A and X
		lda [D + 31]
		tay
		lda [D + 43]				; S as it was before the frame was aligned
		tcs
		tya
		pld
		rtl
```

The [W65C816 Assembler](assembler-w65c816.md) page describes the syntax.
