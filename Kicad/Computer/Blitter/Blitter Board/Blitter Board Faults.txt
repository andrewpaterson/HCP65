HCP65 Blitter Board - schematic faults
======================================

1. The Flags & Interrupt's ~{Reset} (B8 pin 32) isn't connected

   B8 is a Flags & Interrupt, whose pin 32 is ~{Reset}: it is what clears
   Enable.  The HCP65:Flags_Interrupt symbol names the pin N.C., so it is
   left unconnected here (the netlist's unconnected-(B8-N.C.-Pad32)), and
   the Flags board's input floats.

   Effect: reset doesn't turn the board's Enable off, and Enable can come
   up on or change by itself.

   Fix: once the symbol's pin 32 is ~{Reset}, wire it to ~{Reset} (Device
   Decode Stage A's ~{Reset}_OUT).  See Component Boards/Flags Enable
   Interrupt/Flags Enable Interrupt Faults.txt.

2. ~{Done} goes to a pin of the Graphics Signals board that isn't connected

   The HCP65:Graphics_Signals symbol has ~{Done} on pin 4 and calls pin 9
   N.C.  On the Graphics Signals board (its schematic and its PCB) ~{Done} is
   J7 pin 9, and J7 pin 4 goes nowhere.  So the comparator's ~{C=A} (B17 pin
   40) reaches nothing on B19, and its ~{Done} input (IC2's two resets) floats.

   Effect: reaching the stop count doesn't clear Running or Counting, so the
   copy doesn't stop; and as floating inputs the resets can clear them at any
   time.

   Fix: ~{Done} on pin 9 of the symbol (or on pin 4 of the Graphics Signals
   board).

3. The data bus is the wrong way round at the Device Buffer

   The slot's DD0 (J5 A28) is on B16 pin 31 (D0_IN/OUT), whose other side is
   pin 34 (D0), and pin 34 is on the board's D7.  DD7 (J5 A21) comes out on
   the board's D0 the same way, and so on between.  The SD Card Board, which
   has the same buffer and the same slot pins, has DD0 on pin 24 and so on its
   D0.

   Effect: every byte the processor writes to a register, or reads from one
   or from the ROM, has its bits in the reverse order.

   Fix: the DD labels on B16's IN/OUT pins in the other order (DD0 on pin 24
   to DD7 on pin 31), as on the SD Card Board.

4. The source address, destination address and count can't be loaded while the board is idle

   The Counter 24bit's and the Counter 16bit with IO's counters are 74LVC161s,
   which load on a rising clock edge while ~{PE} is low.  Their clock is CLK1,
   and the Graphics Signals board holds its clock flip-flops (IC10) in reset
   while Running is low: CLK1 is high and still whenever nothing is being
   copied.

   Effect: a write to the Source Address or Destination Address
   registers (B1, B12) does nothing unless a copy
   is running and a CLK1 edge falls inside the write.

   Fix: a clock for the loads that runs while the board is idle (CLK1 not
   stopped, or the write strobes made into the counters' clock while idle),
   or counters that load without a clock.

5. ~{Load Count Start} never goes low

   On the Graphics Signals board IC3 (74LVC74) is clocked by Write Start with
   its D high, and ~{1Q} is ~{Load Count Start}.  Its reset (~{1RD}, pin 1)
   is CLK0, which is low whenever the board is idle, and still low when Write
   Start rises: Running is only then being set, and CLK0 first rises on a Main
   CLK edge after that.

   Effect: the flip-flop is clocked while it is held in reset, so the count is
   never loaded with the start count.  It carries on from where the last copy
   left it (0 after a reset).

   Fix: the reset from a clock that is high while idle (CLK2), with the load
   held until the count's clock has had an edge; see the fault before this
   one, as the load needs that edge too.

6. Transparency Enable is the wrong way up

   On the Graphics Transparency board IC6 (74LVC1G32) ORs Transparency Enable
   with the comparator's ~{P=Q} to make ~{Transparent}.  Here Transparency
   Enable is the Flags board's F0 (B8 pin 18), bit 0 of the flags as written.

   Effect: with bit 0 set no pixel is transparent, and with it clear the
   transparent colour is left out.

   Fix: F0 through an inverter, or the flag documented as "opaque".

7. Which way round the four clocks run depends on when Start is written

   On the Graphics Signals board CLK0 is a flip-flop that toggles on Main CLK's
   rising edge and CLK3 one that toggles on its falling edge, both released
   from reset when Running is set.  Running is set by the write strobe, not by
   Main CLK, so either edge can come first.

   If the falling edge is first the order is CLK0, CLK1, CLK2, CLK3, as named:
   the addresses are latched (CLK0) a quarter into the read and are steady
   through the write.  If the rising edge is first the order is reversed, and
   the address latches change in the middle of every write strobe.

   Effect: in the second case each byte is written to its address and the one
   after, and an address that changes under a write strobe can write
   elsewhere.  Which case happens isn't settled on this board: it depends on
   how the device write strobe sits against Main CLK on the main board, which
   hasn't been checked.

   Fix: Running taken through a flip-flop on one edge of Main CLK before it
   releases the clocks.

8. The count steps as a write begins, so the last write is cut short

   The count (B5) is clocked by CLK1, whose rising edge is where the write
   half begins.  The write on which the count reaches the stop count is
   stopped by ~{Done} as it starts.

   Effect: N bytes need a stop count of start + N + 1, and the byte after
   them gets a write strobe a few gate delays long, which may or may not
   write.

   Fix: B5's CLK (pin 4) from CLK3, not CLK1, so that the count steps as each
   read begins.  Counting is set by the first CLK3 edge, so the count doesn't
   step on it: the count is start + k through byte k, ~{Done} comes as byte
   N's read would begin, and what is cut short is a read.  The stop count for
   N bytes is then start + N.  The address counters stay on CLK1.

Also, not wiring faults but what the board does as drawn:

  - ~{Done} is a level: it stays low while the count is the stop count.
    Until one of them changes, Running can't be set again and the interrupt
    comes back on the next Main CLK after it is cleared.
  - Nothing resets Running: after power on it can be set, and the board
    copying.
  - A transparent pixel leaves the internal data bus undriven through the
    write half (the holding latch's outputs are enabled by ~{Write}), while
    the comparator that decides transparency is reading it.
  - The count is 15 bits: C15 isn't connected and the comparator's C15 is
    grounded, so a stop count with bit 15 set is never reached.
  - There is no wait for ~{Main Access}: without it the counts go on and the
    bytes are skipped.

The board also uses standard boards with faults of their own, which it has
with them (see each one's Faults file in Component Boards):
  - Clock Hold Standard: a NOR where an OR is needed, so the clock hold code
    is fought over on every cycle.
  - Counter 24bit: its upper 20 bits count whether or not Count Enable is
    high, whenever the low nibble is $F.
  - Counter 16bit with IO: the same as the Counter 24bit, on its upper 12
    bits.  The count's clock only runs while it is counting here, so it does
    no harm.
